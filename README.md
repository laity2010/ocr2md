# ocr2md

`ocr2md` 是一个专用于 OCR Markdown 标定的 VS Code 扩展。项目仅保留四个工作模块：

- **章节定界**：合并序列 Markdown、维护定界工作稿，并按一级标题导出章节。
- **章节标题**：在章节工作稿中检查和调整标题层级，显示相对 `chapters/` 原件的增删改。
- **注释**：扫描注释引用与正文，提取或手工补全注释号，按号匹配排序，并维护订正工作稿。
- **图片**：扫描图片标题、链接、文本和 HTML，支持下载外部图片。

各模块的数据表统一支持 `已删除` 软标记。被标记的记录会保留用于审计，但不会参与订正、配对、导出或图片下载。

数据表共用 `多选`、`行号`、`行类型`、`预览` 四列，默认按行号升序。单击“行号”“行类型”或“预览”可设为主排序；按住 `Shift` 再单击其他列可追加多列排序，箭头后的数字表示排序优先级。工作稿相对原件的新增、修改、删除行会着色；行号跟随工作稿插行、删行同步调整。点击预览时，侧栏表格留在左侧，右侧编辑区上半为源码并定位到该行，下半为同一文件的 Markdown Preview。行号跟随、增删改着色和右窗布局都是数据表统一特性，标题、注释、图片模块同样适用。

章节定界模块在共用表之上增加自己的 `章节文件` 列。一级标题未分配时会着色；可在列内填写，或先多选再点「分配章节文件」。该列不是数据表的一般列。导出按这些分配写入 `chapters/章节名称/`。

注释模块在共用表之上增加自己的 `注释号` 列，默认按注释号、再按行号升序。该列不是数据表的一般列。提取不到注释号的行会着色提示手工输入；“匹配注释对”按注释号配对引用和正文，并标出待补引用或待补正文。注释配对状态与图片本地路径仍显示在预览单元格内。

## 工作目录树

侧栏目录按处理状态显示为固定工作流树，而不是把 Markdown 文件平铺：

```text
工作目录
├── ocr
│   └── 未带章节定界 YAML 标记的原始序列 Markdown
└── chapters
    └── 章节名称/
        ├── 章节名称.md              章节定界原文件
        ├── 章节名称.working.md      工作稿
        ├── 章节名称.ocr2md.json     工作表数据结构
        ├── imgs/                    章节图片源文件
        ├── 标题
        ├── 注释
        └── 图片
```

- Markdown 开头的 YAML 没有 `ocr2md_chapter_split: true` 时，文件归入 `ocr`，并按自然序参与合并。
- 旧版输出目录 `output/` 与 `output_chapters/` 不参与新工作流扫描，也不会被删除。
- “创建/打开定界工作稿”将 `ocr` 中的序列文件拼接为工作目录根层的 `.ocr2md-merged.working.md`。
- “导出章节”写入 `工作目录/chapters/章节名称/`，该目录是这一章的内容工作目录：定界原文件、工作稿、工作表、图片及其他章节文件都放在这里。原文件写入 `ocr2md_chapter_split: true` 等章节定界 properties。
- 工作稿相对原件有改动时，章节 YAML 写入 `ocr2md_chapter_changed: true`，目录树中该章节会着色并标注“已变动”。
- 点击 `chapters/章节名称/标题`、`注释` 或 `图片`，打开该章工作稿；数据表只处理这一章，增删改相对章节原件比较。

## 开发运行

```bash
npm install
npm test
code .
```

在 VS Code 中按 `F5` 启动扩展开发宿主，然后打开包含 Markdown 文件的目录。

## 数据与输出

- `.ocr2md/`：章节定界合并基线等扩展内部数据。
- `.ocr2md-merged.working.md`：章节定界合并工作稿。
- `chapters/章节名称/`：该章内容工作目录。含定界原文件、工作稿、工作表 sidecar、`imgs/` 图片及其他章节文件；有工作稿改动时原文件 YAML 含 `ocr2md_chapter_changed: true`。

源 Markdown 不会因为数据表中的 `已删除` 标记而被删除。
