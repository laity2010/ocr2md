# ocr2md

`ocr2md` 是一个专用于 OCR Markdown 标定的 VS Code 扩展。章节侧包含四个标定模块和一个只读派生检查模块：

- **章节定界**：合并序列 Markdown、维护定界工作稿，并按一级标题导出章节。行类型提供“已忽略”：记录仍保留在 sidecar 和内部标定中，但立即从数据表隐藏，不再作为章节起点参与章节文件分配或章节导出，也不会删除工作稿原文。
- **章节标题**：在章节工作稿中检查和调整标题层级，显示相对 `chapters/` 原件的增删改；数据表以当前 `.working.md` 为准，因剪切/移动而已从工作稿消失的旧位置不会继续显示为删除候选。工具栏提供默认勾选的「为标题编号」开关；勾选时，预览列和按标定导出都按章节内标题出现顺序显示/输出三位全局序号前缀，例如 `# (001) 标题`、`## (002) 标题`；取消勾选后预览与导出都不带编号。开关按工作区记忆，工作稿原文不改。
- **注释**：扫描注释引用与正文，提取或手工补全注释号，按号匹配排序，并维护订正工作稿。
- **非法断行**：候选主要由章节工作稿自动派生，扫描疑似由 OCR/版面换行造成的错误段落边界；目测发现漏检时，可在 `.working.md` 中把光标放在断行前正文行或两段之间的空行，右键「标记此处为非法断行」手工加入。表格显示 checkbox、断行位置、行类型、上一行、下一行、合并预览和判断；上一行仅预览断点前 10 个字符，下一行仅预览断点后 10 个字符，合并预览仅显示合并点附近 20 个字符。行类型可标为“合并”或“已忽略”，人工加入项显示“人工加入”，人工决策写入 sidecar；候选位置本身仍基于原文定位，不直接修改原文。执行“按标定导出”或“导出标定到trans”时，`合并` 会在输出层删除该断点及其间空行并合为同一正文行；行尾连字符拆词会去掉连字符直接拼接，`已忽略` 保持原文断行。
- **嵌入块**：单独的 `>` 行列为「嵌入块首」；图片、HTML、内嵌标题和紧挨着的说明共用同一序号，直到下一个 `>`。章节正文不会收成嵌入文本。行类型为嵌入块首、内嵌标题、嵌入链接、嵌入 HTML、HTML 表、嵌入文本、已忽略。误扫入嵌入块的行可标为“已忽略”：记录仍保留在 sidecar 和内部标定中，但立即从数据表隐藏，同时退出嵌入序号、嵌入导出和图片下载，并在按标定导出时恢复为普通正文。数据表显示序号；导出时嵌入块内部各行严格按源码行号顺序输出，不按行类型重新排序。「下载图片到本地」会下载全部外部图片，并把状态写入标定以便断点续传。VS Code 粘贴产生的本地 Markdown 图片会预先显示实际导出路径，并在导出时复制到章节 `imgs/`，使用带文件修改时间戳的唯一文件名，原图和工作稿不改动。「按标定导出」按标题、注释、嵌入块规则写入 `chapters/章节目录/output/`；「导出标定到trans」写入 `chapters/章节目录/trans/章节文件.md`，并在 YAML 中写入 `ocr2md_format_calibrated: true`。

数据表统一隐藏行类型精确为 `已忽略` 的记录；这些记录仍保留在 sidecar 和内部标定中。该规则不影响注释中的 `忽略`；非法断行现已使用统一的 `已忽略`。各模块的数据表仍统一支持 `已删除` 软标记；被标记的记录会保留用于审计并继续显示，但不会参与订正、配对、导出或图片下载。

数据表共用 `多选`、`行号`、`行类型`、`预览` 四列，默认按行号升序。点击任一模块的数据表预览定位源文件时，源码窗口统一高亮当前候选覆盖范围，并对该源码窗口中的所有真实物理换行以编辑器 Decoration 着色显示 `↵`；换行可视化属于源码窗口统一特性，与模块无关，也不会写入 Markdown。单击“行号”“行类型”或“预览”可设为主排序；按住 `Shift` 再单击其他列可追加多列排序，箭头后的数字表示排序优先级。工作稿相对原件的新增、修改、删除行会着色；行号跟随工作稿插行、删行同步调整。点击数据表预览时，打开源文件并定位到该行。Markdown Preview 由用户自行打开，插件不控制预览窗格。行号跟随和增删改着色是数据表统一特性，标题、注释、嵌入块模块同样适用。

章节定界模块在共用表之上增加自己的 `章节文件` 列，并提供「设置章节文件」：勾选一级标题后，可统一序号归入同一章、从起始序号依次递增生成独立章节，或对已有序号整体偏移。文件名由序号加标题文本生成。误识别或暂不参与定界的行可标为“已忽略”；它会立即从表中隐藏，但仍保留标定状态，并且不参与设置章节文件和导出章节。该列不是数据表的一般列。导出按这些分配写入 `chapters/章节名称/`。

嵌入块模块在共用表之上增加自己的 `序号` 列，默认按序号、再按行号升序。该列不是数据表的一般列。 在嵌入块源码窗口右键「将当前行加入到数据表」属于显式人工标定：执行后立即加入/恢复该行、重新计算嵌入序号并刷新数据表，不需要先保存工作稿；若该行此前为 `已忽略`，会恢复为当前内容对应的默认嵌入行类型。

注释模块在共用表之上增加自己的 `注释号` 列，默认按注释号、再按行号升序。该列不是数据表的一般列。提取不到注释号的行会着色提示手工输入；“匹配注释对”按注释号配对引用和正文，并标出待补引用或待补正文。注释配对状态与图片本地路径仍显示在预览单元格内。

## 工作目录树

侧栏目录按处理状态显示为固定工作流树，而不是把 Markdown 文件平铺：

```text
工作目录
├── ocr
│   └── 未带章节定界 YAML 标记的原始序列 Markdown
├── chapters
│   └── 章节名称/
│       ├── 章节名称.md              章节定界原文件
│       ├── 章节名称.working.md      工作稿
│       ├── 章节名称.ocr2md.json     工作表数据结构
│       ├── imgs/                    章节图片源文件
│       ├── output/                  按标定导出的 Markdown
│       ├── 标题
│       ├── 注释
│       ├── 嵌入块
│       ├── 非法断行              疑似 OCR 断行候选 + 合并/已忽略标定
│       └── trans/                   已完成格式标定后的翻译工作区
│           ├── 章节名称.md          格式标定后的源文
│           ├── 文本块               按 <br> 派生的只读结构表
│           ├── 分句                 非内嵌文本块的只读分句表
│           └── 翻译                 逐句翻译、进度与断点续存
└── 翻译服务                         翻译服务设置与连通性测试
```

- Markdown 开头的 YAML 没有 `ocr2md_chapter_split: true` 时，文件归入 `ocr`，并按自然序参与合并。
- 旧版输出目录 `output/` 与 `output_chapters/` 不参与新工作流扫描，也不会被删除。
- “创建/打开定界工作稿”将 `ocr` 中的序列文件拼接为工作目录根层的 `.ocr2md-merged.working.md`。
- “导出章节”写入 `工作目录/chapters/章节名称/`，该目录是这一章的内容工作目录：定界原文件、工作稿、工作表、图片及其他章节文件都放在这里。原文件写入 `ocr2md_chapter_split: true` 等章节定界 properties。
- 工作稿相对原件有改动时，章节 YAML 写入 `ocr2md_chapter_changed: true`，目录树中该章节会着色并标注“已变动”。
- 点击 `chapters/章节名称/标题`、`注释`、`嵌入块` 或 `非法断行`，打开该章工作稿；数据表只处理这一章。`非法断行` 的候选由原文派生，但“合并/已忽略”人工决策参与标定保存；其余章节模块的增删改相对章节原件比较。
- “非法断行”同时检查普通正文的连续物理行和由一个或多个空行分隔的段落边界，优先标出“空行前正文未自然结束”“下一段小写续写”“行尾连字符拆词”等高疑似情况；句末标点后的 `[*n]` / `[^n]` 引用会先剥离再判断，`Source:` / `Notes:`、标题、列表、引用、表格、HTML、代码块、块级公式、图片/嵌入和显式 Markdown hard break 会主动排除。自动扫描漏检时，在当前章节 `.working.md` 中将光标放在断行前正文行或中间空行，右键「标记此处为非法断行」；插件自动取得上下最近的非空行，生成“合并 / 人工加入”候选。若同一断点此前已被标为“已忽略”，再次人工标记会恢复为“合并”。0 条时表格仍显示表头并明确提示扫描已完成。候选表用于人工确认；checkbox 支持统一多选批量设置“合并/已忽略”，并可保存/重新加载标定。
- 每个 `chapters/章节名称/trans/` 是该章自己的翻译工作区；`**/trans/**` 不会重新参与 OCR 或章节源文件扫描。
- 若升级前存在旧的 `工作目录/trans/章节名称/`，刷新工作区时会在新目标不存在的前提下迁移到 `chapters/章节名称/trans/`；目标已存在时不覆盖，并在 `Output → ocr2md` 记录跳过原因。
- 工作目录根层的 `翻译服务` 是固定节点。点击后右侧切换为设置页而不是数据表；当前支持 DeepL 与 OpenAI GPT 两个独立服务。两者 API Key 分别使用 VS Code `SecretStorage` 保存，不写入工作区文件，也不会回显到 webview；GPT 可设置模型（默认 `gpt-5.4`）和翻译提示词。设置页可分别保存并真实测试当前服务，测试结果显示 HTTP 状态、译文和服务器原始响应。
- 展开 `chapters/章节名称/trans` 可进入“文本块”“分句”“翻译”三个阶段。“文本块”按独立的 `<br>` 行划分，显示真实起始行号、文本块类型和预览，当前自动区分标题、内嵌、文本、注释正文。
- “分句”完全跳过内嵌文本块；标题整体视作一句，文本与注释正文使用 `Intl.Segmenter` 分句，并合并 `Mr.`、`Dr.`、`Fig.`、姓名首字母等已知误切。OCR 段落内部的物理换行在分句时临时视为空格，但保留原字符偏移，因此点击句子预览仍能精确定位回该章 `trans` Markdown。
- 分句表为只读派生数据，显示源行号、来源文本块（`B001` 等）、来源类型、句内序号和句子预览；不会修改 `trans` Markdown。
- “翻译”以普通分句作为固定的一一对应单元；工具栏可选择当前要补译的服务（DeepL / GPT）。DeepL 每次发送一句并将完整父文本块作为 `context`；GPT 通过 OpenAI Responses API 接收同一句和父文本块上下文，并使用可配置翻译提示词。合成块（Figure/Notes/图片说明/表格说明等）另外抽取可读文字子内容作为 `C` 类翻译单元；图片、HTML、`<embed>`、已有 callout 与块级公式本身不送翻译。
- 翻译表显示文本块、单元序号、来源类型和原文，并为每个翻译服务横向增加独立译文列（当前为 `DeepL译文`、`GPT译文`）；每格独立显示译文、状态、失败信息和模型信息。普通句显示 `S` 单元，合成块文字显示 `C` 单元。工具栏的进度条只统计当前选择的翻译服务，因此 DeepL 已完成不会阻止继续补 GPT。
- 每个章节的翻译断点保存在 `chapters/章节名称/trans/.ocr2md-translations.json`。每处理一个翻译单元都会原子写回状态文件。翻译复用不再把文本块 id、行号或句内位置当作唯一身份：每个单元使用规范化正文生成稳定 `sourceFingerprint`，因此调整 `<br>`、嵌入块、标题/文本块边界或其它只改变版面位置的输出后，只要句子正文没有变化就直接复用旧译文；相同正文在一章内重复出现时，再使用前后翻译单元生成的 `contextFingerprint` 消歧。旧版 v1 状态没有指纹也可直接加载：当新旧单元数量和正文内容多重集合完全一致时，可按旧翻译写入顺序安全回填上下文指纹。真正正文改变时仍不会错误复用旧译文。
- 翻译前统一保护 Markdown 非翻译结构：行内/块级 LaTeX、脚注引用与脚注正文前缀、HTML 标签、Obsidian wikilink/embed、图片、URL、代码片段及标题/列表/引用等行首结构。普通 Markdown 链接只保护 `[` 与 `](目标)` 结构和链接目标，中间的显示文字仍参与翻译。发送到 DeepL 的受保护结构使用带唯一 ID 的 XML 占位标签，并启用 `tag_handling=xml`（v2），避免普通文本占位符被翻译引擎改写；DeepL 返回后先检查所有占位标签是否完整，再按原字节恢复，缺失时该单元才记为失败。分句阶段也会对 URL、wikilink、代码、链接和行内公式做等长屏蔽，避免标点误切且不改变源码字符偏移。独立的多行 `$$ ... $$` 块不进入分句、不翻译、不产生锚点。

## Obsidian 双向交叉互译导出

“翻译”模块可在「导出译文」下拉框选择 DeepL 或 GPT；所选服务全部单元完成后即可点击「导出双向互译」。输出目录固定为当前章节自己的 `chapters/章节名称/trans/`，不再要求选择或输入路径。Obsidian 交叉引用路径根据该 `trans` 目录相对于当前工作目录（Vault 根目录）的实际路径自动计算。导出前会先完整生成并校验三份输出；校验失败时不写正式输出文件，也不会修改 `chapters/章节名称/trans/章节名称.md`。`org2trans`、`trans2org` 与纯译文 `trans` 三份文件采用成组提交：已有版本会临时备份，三份都成功写入才替换完成；异常时恢复旧版本。

实际目录与文件名：

```text
chapters/章节名称/trans/
├── 章节名称.md
├── .ocr2md-translations.json
├── org2trans <章节文件名>.md
├── trans2org <章节文件名>.md
└── trans <章节文件名>.md
```

普通文本使用稳定的一一对应锚点 `^sid-<文本块序号>-<句内序号>`。`org2trans` 以原句为正文并嵌入 `trans2org` 对应块；`trans2org` 以译句为正文并反向嵌入 `org2trans`。Obsidian 链接使用实际 Vault 相对输出路径和实际文件名，但链接目标不带 `.md` 扩展名。

`trans <章节文件名>.md` 是纯译文版：保留译文正文与原 Markdown 结构，不输出 `sid`、交叉互译 callout 或跨文件锚点链接；图片、HTML、脚注编号、链接、代码和公式等结构继续原样保留。

合成块不创建 `sid/bid`，也不创建跨文件 embed。Figure 标题、Notes、图片说明等原/译文字在块内直接以 `>>[! ds]-` 内嵌 callout 双向呈现；图片链接、HTML、`<embed>` 和其他结构原样保留。多行 `$$ ... $$` 公式原样穿透，绝不翻译、分句、加锚点或 callout。

导出校验至少包括：双向 `sid` 集合一一对应、交叉引用路径正确、合成块无跨文件锚点、块级公式无锚点/callout、无残留保护占位符，以及图片/HTML/脚注/公式未丢失。只要仍有待翻译或失败单元，「导出双向互译」保持不可用。

## 开发运行

```bash
npm install
npm test
code .
```

在 VS Code 中按 `F5` 启动扩展开发宿主，然后打开包含 Markdown 文件的目录。

## 数据与输出

- `.ocr2md/`：章节定界合并基线等扩展内部数据。
- `.ocr2md-merged.working.md`：章节定界合并工作稿。
- `chapters/章节名称/`：该章内容工作目录。含定界原文件、工作稿、工作表 sidecar、`imgs/` 图片及其他章节文件；有工作稿改动时原文件 YAML 含 `ocr2md_chapter_changed: true`。
- 工作稿 Markdown 是正文真源。sidecar JSON 只存 `atomId` 标定（行类型、注释号、章节文件等），不能单独还原正文。数据表先扫描工作稿得到当前块，再按 `atomId` 接上标定；行号始终来自工作稿当前位置。

源 Markdown 不会因为数据表中的 `已删除` 标记而被删除。
