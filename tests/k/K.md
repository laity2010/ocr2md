## 数据与“标准答案”的独立性

1. **固定输入**：`data/manifest.json` 中记录现有仓库原始 MinerU JSON、转换 MD 样本及只读 PDF 的 SHA-256。运行时必须用隔离副本，不能将工作区母文档当作稳定输入。PDF 当前存于本机 Git 忽略工作区，**尚未成为可随项目迁移的便携固定测试夹具**；这是正式 K 认证前的待办。
2. **两个不同的初始状态**：仓库固定 `.minerujson.md` 样本为 224 个块锚点、21 个标题、0 条章节标定；当前用户已编辑母文档为 224 个块、19 个标题、14 条标定。母文档的 SHA 只用于冻结当日**观察记录**，不当作持续变化工作文件的测试标准答案。
3. **预期输出**：每项 K 剧本有独立版本化 `expected/` 真值（文件、JSON、状态序列、hash、数值与可视性容差）。**不能在运行时调用被测生产函数，动态生成自己的正确答案**。除初始化的固定数据外，实际操作生成的标准答案要人工核实后才冻结。
4. **K 验收失败即为失败**：优化生产代码不得顺手修改固定输入、标准答案、容差或 K 定义。若产品行为确需改变，先作为独立需求审议 K 基准版本变更，再实施功能修改；不能改答案让失败变绿。

## 建设航路（不变更 V6 生产代码）

| 阶段 | 交付物 | 退出标准 |
|---|---|---|
| **WP0 冻结与登记（本轮）** | Git 冻结标记；上述 K01–K08 表、数据指纹清单及只读预检 | 生产仓库代码与发布版本不变；冻结 commit 与数据 SHA 可复核 |
| **WP1 数据与标准答案** | `fixtures/` 的可重现生成方案、PDF 便携性处理；八项剧本独立 `expected/Kxx/` | 标准答案由冻结版本实际演练并人工核对；记录输入哈希、输出哈希、容差来源，禁止自证式答案 |
| **WP2 独立 K 剧本** | `cases/K01…K08`，仅用公开 API/真实 UI 执行可重复测试 | 每项至少一个端到端剧本及负面案例；所有服务、磁盘、授权都与正式用户数据隔离 |
| **WP3 K Runner / 门禁** | 一个 `node tests/k/run.mjs` 入口；每项可见 PASS/FAIL、差异及证据；失败时非零退出 | 不允许跳过失败项、修改预期后立即放行、静默降级；不污染 `ui/` 核心代码量 |
| **WP4 初始认证** | 在冻结 Git 版本运行完整 K01–K08，再运行现有模块回归；冻结 K v1 基准 | **8/8** K 项及被覆盖的重要模块均通过、原始 SHA 无变化、用户核定标准答案后，K v1 才生效 |

**代码量口径**：核心统计只包含 `ui/` 与 `packages/minerujson-md/src/` 下的 JS/TS/CSS，冻结时 **3,501 行**；`tests/k/` 中的 K 表、夹具、expected、脚本、runner 和报告不计入。K 测试代码多并不意味着生产代码膨胀。此次只冻结功能开发，**不实施新的功能优化**，也不修改 `AGENTS.md`、冻结实验或正式发布目录。
