## 覆盖口径

- 审计入口：`python3 audit-am-boundaries.py`；回归：`python3 audit-am-boundaries-test.py`。
- 权属来源：七个模块入口及正式 API 仍以 Git 管理的 `tests/am/registry.sql` 为准；新增的 `audit-am-ownership.json` 是 27 个 UI JS 文件的审计级**实现文件归属补充**，不替代 AM 模块/API 登记。
- 实测分类：七个模块入口、十个模块内部辅助文件、四个共享基础文件、六个应用编排/辅助文件；四类合计 27 个，**不把 20 个辅助文件膨胀为 20 个组件**。
- 检查：所有静态相对 JS import/export 与常量动态 import；文件存在与归属；跨模块导入对应的 `access_edges` 登记、允许引入的导出符号；共享基础库的允许消费者；直接 `viewStore.setState({field:...})` 写入口。
- 已审视 14 条跨模块 JS 导入关系和 17 条对共享基础库的 JS 导入；均在本基线申明的依赖约束内。**代表性 AM 调用边 42 条与全仓模块间导入不是同一计数口径**。

## 需继续关注的边界问题

1. `ui/view-store.js` 是跨模块共享的可变 Zustand 状态总线；`ui/outline-grid.js` 直接写 `outlineCount`，`ui/workspace.js` 直接写 `activePanel`。两处既存写入在归属清单中明确审阅，不因静态检查 PASS 被归为“无债务”。新写入字段或新增写入方现在会被检查器阻拦；今后可考虑把写操作收敛为窄的公开方法。
2. AM API 清单中 `M02–M07` 的 `source_file` 为 `ui/workspace.js`（归属 L），但语义登记为 M 预览功能。这是已有的跨权属 API 记账，需要进一步明确是布局提供的 PreviewPanel 还是 MD Preview 模块对外 API。**不在 WP2 擅自改动 API 或业务源码**。
3. `ui/main.js` 的 DEV 接缝 `__v6cm6` 暴露具有副作用的控制句柄，原 AM 已标成 test_only；WP2 静态 import 审计不会因此证明 DEV 接缝真正只读。
4. 此次检查**不是 JavaScript AST 全静态+动态语义证明**：非字面量动态加载明确 FAIL；DOM、Zustand 订阅、属性调用链与运行时注入仍需结合现有 `am.py` 42 条边及独立人工抽审。静态 PASS 不等于跨模块语义全覆盖，也不等于整仓 0 debt。

## WP2 全量回归中的测试时序故障（Mac）

独立 Mac 全量 AM 第 16 个脚本媒体粘贴的本地 GET (`/media/<hash>.jpg`) 在 Node 23.11.0 曾连续两次出现 `ECONNRESET`，分别位于端口 5594/5593，导致 26/27、135/139。独立端口 6595/6596 的 Chrome/WebKit 诊断则两者全量功能断言 PASS；这不能证明底层连接复用是唯一原因。审计契约对此处只读 GET 做有限重试并记录发生情况，不改 Python 服务、业务模块或写入调用。旧失败日志保留于隔离本机证据目录。
