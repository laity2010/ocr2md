# OCR2MD 后续开发 · Linux 平台兼容性要求（可直接发给 GPT 侧）

背景：三轮审计 + 主线审计（Ubuntu 24.04 x86_64）证明，卡住审计的东西绝大多数不是产品逻辑，而是开发机假设漏进了代码和测试。唯一真正的产品问题是 LaTeX 审阅计数重开后的恢复竞态（已在 ea5b0ca 用 `ui/main.js` +5 行产品修复解决）。以下要求请作为后续开发的硬性约束，而不是审计时再排障。

## 1. 配置里不写本机绝对路径
- 反例：vite 配置写死作者本机的 iCloud PDF 路径，首轮因此挂了 22 条。
- 要求：路径一律用环境变量（如 `V6_PDF_PATH`）或相对路径；缺失时明确报错，不静默回落到某台开发机。

## 2. 夹具生成必须跨平台
- 反例：媒体夹具只认 macOS 的 `sips`，Linux 上 19 条挂掉。
- 要求：夹具生成只用跨平台工具，或自带垫片（如 Chromium sips 垫片）；在 Linux 上实跑一次夹具生成再合入。

## 3. 不要假设 loopback 上 Secure Cookie 可用
- 反例：Linux WebKitGTK 不存 loopback HTTP 的 Secure Cookie，导致解锁后写 403，7 条挂掉。
- 要求：涉及 Cookie / 解锁写回的逻辑，必须在 Linux Chromium + WebKit 双引擎下验证；需要适配器就把适配器写进产品/测试基础设施，不要只在审计时临时绕过。

## 4. 端口预检不把 TIME_WAIT 当占用
- 反例：旧端口预检把 TIME_WAIT 误判为端口被占，拦下正常启动。
- 要求：预检区分 TIME_WAIT 与 LISTEN；复跑场景（上一轮刚结束 1 分钟内再启动）必须能通过。

## 5. 系统依赖要声明、可预检
- 反例：本机缺 libgstreamer 等库时，整轮只能记环境 BLOCKED，无法执行。
- 要求：依赖清单 + 安装开关（如 `INSTALL_SYSTEM_DEPS=1`）+ 启动前预检；缺库时报错要指明缺哪个库，而不是笼统失败。

## 6. CI 里常驻一个 Linux 全量环节
- 要求：新功能合入前跑 Linux 双引擎相关套件；不要等独立审计才第一次在 Linux 上跑全量。主线第三轮补的端口预检和浏览器预检就是正确方向，把它变成常态。

## 7. 修问题修产品代码，不放宽测试
- 正例：ea5b0ca 的修复是产品侧重发审阅计数，测试只是加延迟让竞态确定性复现并加恢复值断言；原最终断言 `latex 1 / 忽略 1` 与 25 秒超时逐字未动。
- 要求：不允许靠改期望计数、放宽超时、删断言来“通过”；测试强化可以，断言放宽不行。

---
验收口径：一个改动算 Linux 兼容，当且仅当它在 Linux 上 Chromium + WebKit 双引擎的相关套件通过，且没有新增“仅 macOS 能过”的假设。审计的职责回归验功能和契约，不再先当半天跨平台排障。
