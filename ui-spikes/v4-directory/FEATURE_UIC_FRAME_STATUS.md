# OCR2MD v4.7.2 · 框架统一状态栏、版本弹窗与 AG 顶部精简

## 功能规范（操作 / 需要 / 效果）

- 框架底部**唯一**可见状态栏 `#v4-framework-status` 显示活跃模块名称、最新消息和 ready/busy/dirty/error 等级。模块通过通用 `wcp:module-status` 事件上报 `{moduleId,message,level}`；底座仅验证模块 ID 并缓存每个模块最后的状态，非当前模块消息不会抢占显示。WCP 不读取 DIRjson/工作目录/设置模型，不写用户数据。框架自身异常也显示在该状态栏。
- `ocr2md v4` 顶栏应用名仍可点击打开**版本弹窗**，顶栏不再显示 `v4.*-构建号` 或组件活动摘要。弹窗包含完整构建 ID、应用版本和 WCP 当前组件清单；未知/正在加载仍有明确提示。
- 四种业务界面的 AG 表，直接从 AG Grid 自身列头开始，不再叠放 `章节定界`、`章节元素 · AG 表` 等自定义标题；相关过滤器和起始序号移至原有模块按钮区。PDF/MD 页码缩放保留在预览子窗，不触动已有 AG 列筛选。
- 原 v3 内部状态节点保留给业务监听器和测试读取，但默认不占布局、不产生第二个可见状态条，不自动替换业务组件对象，尊重 WCP ResidentHost 驻留行为。

## v4.7.3 · 顶部状态 + 模块路径导航（2026-10-13）

**功能规范**：统一框架状态栏保持原有 `wcp:module-status` 事件、模块状态缓存与等级，仅将显示位置从底部移至最顶部 `ocr2md v4` 版本弹窗按钮右侧的**同一行**；对话框和控制按钮位置不变。顶部为单行 flex，iPad 窄屏时状态文本省略显示，完整文本保留 `title`，不得因此挤落第二排或遮住版本按钮。页面底部不再有状态栏。

**导航业务规则**：工作台右侧的 `<select>` 当前值与每项文案均为 `模块名称：实际完整路径`：

- root：`章节定界：/ocr2md/<工作目录名称>`
- chapters/ 入口：`章节清洗：/ocr2md/<工作目录名称>/chapters/`
- 已发布 MD：`章节清洗：/ocr2md/<工作目录名称>/chapters/<文件名>.md`

目录/文件真实路径作为 `option.value` 原样保留；**选择 chapters/ 后进入第一份章节 MD，并将选中的 option 同步为这份 MD 完整文件路径**，避免出现“显示目录但实际编辑某文件”的歧义。选择工作目录 root 切回章节定界，保留未保存草稿阻拦和 CQE 授权约束。WCP 内核不得据路径猜测业务路由；业务显示由章节插件决定。

## v4 构建标牌 · BLD-01（2026-10-14，后续用户需求覆盖 STAT-05 的“不显示构建号”约定）

**功能规范（操作 / 需要 / 效果）**：每次成功构建 v4，构建脚本根据 Mac 主机的 UTC+08 时间生成 `v4-YYMMDD-HHMM` 简短 ID（例如 `v4-261014-0757`），完整到秒时间写入 `build-info.json`。顶栏应用标牌**固定显示** `ocr2md  v4-YYMMDD-HHMM`，与现有 WCP 框架状态同一行；点击标牌仍打开组件版本弹窗，显示相同短 ID 和精确时间。标牌在**构建时**写入静态 HTML，禁止页面打开时生成“假版本”。

**发布不变量**：`scripts/build-modules.mjs` 完成插件编译后才运行版本标记；所有源 HTML、应用入口、插件注册表及业务 bundle 的 SHA-256 统一写入 `build-info.json`。`scripts/publish.mjs` 校验全部部署产物哈希及顶栏/弹窗 ID 一致，否则失败，防止混合新旧资源却显示新版号。缓存键绑定短 ID。**构建、拷贝本地静态目录并不等于 4292/公网已部署**；只有检测实际服务器返回相同构建 ID 且对应资源哈希完全一致，才能报告在线版本已更新。不要在未验收时将用户已有未保存草稿所在的旧页面静默替换。

**UIC**：

| 编号 | 初始状态 / 用户动作 | 期望效果 | 自动化 |
|---|---|---|---|
| BLD-01 | 构建 v4 | 生成 `v4-YYMMDD-HHMM`，完整时间到秒，ID 是实际构建产物的一部分 | `build-modules.mjs` + `publish.mjs` |
| BLD-02 | 打开新版本浏览器顶部 | `ocr2md` 旁显示精简 ID，宽窄屏与 WCP 框架状态同行，标签不会被挤出视口 | `tests/buildVersionBrowser.mjs`：Chromium/WebKit × 1024/768 |
| BLD-03 | 点击版本标牌 | 弹窗完整显示相同短 ID 和到秒时间 | 同上 |
| BLD-04 | 页面 HTTP 实际部署 | `build-info.json` / HTML 标牌 / app.js / 注册表 / 插件 bundle hash 一致；任一不一致拒报上线成功 | 本机 `buildVersionBrowser.mjs` 可自动验收；4292 与公网分别单独验证 |

当前人工审核状态：待用户查看实际设备顶栏；运行中 4292 如未切换则不声称已经生效。

## BLD-05 · iPad 自动接收版本（2026-10-14）

**业务边界**：Web 应用无法读取实体 iPad 正在连接的 Wi-Fi SSID、是否使用蜂窝网络，亦不能从过期的设备调试报告推断当前网络。版本弹窗按页面自身的 URL 判断访问的是局域网/本机还是公网域名，明确说明这不是物理接入网络。

**版本传送契约**：统一执行 `node ui-spikes/v4-directory/scripts/build-test-push-ipad.mjs`，自动编译 v4、核对资产哈希、在 Chromium/WebKit 以本地模拟 WCP 完成版本/弹窗/安全更新回归，再发布到已经存在、已授权的 4292 局域网开发入口。`release-lan.mjs` 先核对实际运行服务、后端进程启动时间是否晚于核心 Python 源码修改时间，若存在“新前端+旧后端”风险则**终止发布**，保留运行服务与旧标牌；不得为绕过此门禁而单独覆写 HTML。只操作已有 LAN 候选目录，保留上一版本，绝不自动发布公网稳定版或改写用户书籍。公网部署须先配置并验收独立候选入口和授权后才可纳入分发。

**iPad 更新契约**：打开的 V4 页面在可见状态约每 60 秒或重新切回前台时获取同源 `build-info.json`；仅在服务器新版本清单与实际上线 HTML 标牌一致、WCP ready、页面无 dirty、编辑输入未聚焦且未在切换模块时，才执行整页切换。否则在顶部提示“新版本…保存后更新”，绝不丢弃草稿。离线、403/未授权、过渡期资源不一致时保持旧页面，不循环刷新。旧版尚无监听机制时，首次升级需要一次手动打开新版本入口。

| BLD-06 | WebKit 检出新的版本，但草稿未保存 | 页面不导航、不丢草稿，提示新版本待更新 | `tests/buildVersionBrowser.mjs` |
