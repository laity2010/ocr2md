# FC-V3-MEDIA-DECOUPLE-001 / UIC-V3-MEDIA-DECOUPLE-001

- 目标：章节媒体成为第一份业务上真正解耦的模块。媒体扫描、待下载队列、任务状态、失败分类、409 恢复决策、AG 状态投影、AG 下载状态/失败原因列，均由 `src/modules/chapterMedia.ts` 独占。
- 用户操作：章节清洗→媒体→下载图片（N），查看顶部进度、AG 各行状态和失败原因；切换章节或模块。既有入口不变。
- 需要：用户已进入已发布章节，MD 无未保存改动，Mac Vault 授权正常。原文 PDF/IR 不需要由媒体模块读取。
- 效果：下载成功采用 `imgs/...` 本地路径；单张 404/网络错误继续；409 仅在只读核实整章字节未变时同步版本并继续；真正正文冲突或失去授权终止；顶栏进度及 AG 行内原因始终同步。模块离开再返回可展示当前章节结果。
- 安全不变量：用户未点击不下载；不允许绕过 Mac 服务的 CAS、域名/IP/下载大小/MIME 安全检查；不自动重试不确定的 POST；切书、脏稿、文件版本变化不能覆盖人工编辑；不写入正式测试书籍。工作台只提供 **通用** 文档快照、章节独占事务和 AG 列/行扩展，绝不保存图片 URL、任务进度或媒体错误分类。
- 实现边界：`chapterMedia.ts` 只依赖注入的窄接口（ChapterDocumentPort）并声明 ChapterGridView，不能导入 `V3Workbench`、CodeMirror、AG Grid 实现类或在文档中查找工具栏 DOM。工作台注入按钮元素，模块负责按钮点击与启停；模块拥有行投影、两列 V3 状态展示、完整列顺序（分组→状态→原因→缩略图→文件名→大小）。V2 媒体基础列及缩略图拖拽底层渲染暂共用，防止破坏 V2。V2 `calibrationGrid.ts` 只接受通用列扩展及排序参数，不再写死 V3 mediaTaskStatus/Reason。媒体状态映射从 Workbench 移至媒体模块；工作台只持有可用于其他模块的泛化文档事务、只读 CAS 版本核验与 AG view 注入。
- 自动化：独立媒体控制器核心测试（无需浏览器，覆盖一般错误、CAS、安全中止、状态/列）、模块扫描/注册单测；保留 Chromium/WebKit 媒体/导航/下载原回归；构建与 Mac 后端安全测试。失败要留下准确证据，不为了通过而弱化安全边界。
- 验收标准：以后调整媒体下载失败分类、继续策略等纯媒体业务，只修改 `chapterMedia.ts` 和它的测试，`app.ts` / `workbench.ts` / V2 AG 不再需要修改业务代码。
- 人工审核：待用户 iPad Safari 版本确认与现场下载。
