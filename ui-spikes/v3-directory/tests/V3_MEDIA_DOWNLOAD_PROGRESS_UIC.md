# FC-V3-MEDIA-DOWNLOAD-STATUS-001 / UIC-V3-MEDIA-DOWNLOAD-STATUS-001

- 功能：章节清洗 · 媒体图片下载任务的实时状态、逐项结果及完整终态。
- 操作：在已发布章节中选择“媒体”→“下载图片（N）”；检查顶栏进度和“明细”；完成、失败或中止后查看剩余未下载数及逐项原因。
- 前提：用户在隔离 Mac Vault 中持有已发布章节；扫描出的远程图片来源是当前章节实际引用；下载只由用户显式点击，不在切换模块时自动触发。
- 初始：无任务时仅原按钮；点击开始后媒体 AG 顶栏显示状态（当前 i/N、成功、失败、来源定位），旁边可点“明细”；上方活动状态栏显示“媒体下载 i/N”，不被常规 chapter 状态覆盖。
- 执行中：逐项明确“正在下载/成功采用本地路径/失败及原因”；已失败的 URL 只记录一次、以后继续其它来源，除非版本冲突/目录切换等需中止的错误。禁用重复下载按钮；不推断下载成功，不依赖后台定时重试 POST。
- 终态：无论全成功、部分失败、全部失败、CAS 冲突或意外异常，必须明确显示处理数量、成功、失败、未处理和停止原因；状态持续可查，明细列表显示具体哪个来源失败及服务器给出的错误原因。文件已经部分写入的项目视为已采用，不把未证实的文件显示成成功。媒体模块离开、切换章节时不能把旧任务当作当前章节记录。
- 用户可见状态：媒体 AG 顶栏有常驻本次任务摘要/明细，不依赖隐藏的旧 clean-status；主活动栏显示 busy/error，结束后媒体顶栏仍留终态，包含成功数及未完成数。长地址可截断显示主机和路径，不展开可能含密钥的 URL 查询参数。
- 失败归因：Mac 端保留 DNS、HTTP 状态、网络超时、无法解析/拒绝内网、格式/20MiB、CAS 冲突等可解释的错误类别，不返回含凭证的 Python 异常堆栈；暂时性网关/网络错误不自动重试非幂等 POST。
- 副作用：除当前实际用户请求的单张图片和对应章节 CAS 更新之外不做写入，不碰其它章节/原 PDF/DIRjson；记录只存在当前前端会话。
- 不变量：没有用户点击不得发起 POST；每项失败必须保留原外链；任一异常后任务不能卡在 running=true；真实 Safari 需要人工复核滚动、选中及可读性。
- 自动化：隔离 Vault + Playwright Chromium/WebKit 用被拦截的图片下载 POST 返回成功/失败/冲突，覆盖三种终态；断言可见状态和明细、继续与中止策略、零额外文件写入。Mac 路由异常类型执行模拟验收。
- 证据：`tests/chapterHierarchyBrowser.cjs`（`OCR2MD_TEST_MEDIA_PROGRESS=1`；Chromium + WebKit/iPad 1024px）、`ui-spikes/v2/tests/v3ChapterMediaDownloadSmoke.py`。
- 人工审核：待用户 iPad Safari 验收。

## 2026-10-12 · AG 明细 / 顶部状态栏（UIC 交互修订）

- 操作：在章节清洗的“媒体”模块按“下载图片”。AG **顶栏只能有模块选择、下载图片及该模块的真正工具按钮**，不再显示进度文本、“下载明细”菜单或其他日志控件。
- 预期：顶部页面状态栏（ocr2md 版本右侧的工作台活动状态）显示 `下载 2/11 · 成功 1 · 失败 1`，结束后仍保留最终摘要，直到切换章节/离开清洗；iPad 窄屏不得整段消失。
- AG “媒体”表新增固定可见的 `下载状态` 和 `失败原因` 两列，逐图片对应 `等待/下载中/已下载/失败/未处理`。失败行显示明确的错误文字并可在单元格的标题提示查看完整内容；已成功本地化的行仍有正确状态（通过原 URL + 保存后本地路径关联），不是只有消失的远端行才有结果。没有任务的远端行显示 `未下载`，已本地化的显示 `已采用`。
- 数据副作用与约束不变：AG 状态只在当前前端内存展示，不写回 MD/DIRjson，不自动重试失败 POST；发生冲突时未处理行仍可识别；切换模块、章节不串状态。
- 自动化：浏览器回归断言 AG 额外两列、四种任务状态与行内失败原因；顶栏无下载进度/日志 DOM；顶部工作台状态 busy/error/ready 的完整信息持续显示，WebKit 1024px 触摸尺寸预检，真 iPad Safari 待人工审核。

## 2026-10-12 · 单张 409 的安全恢复（UIC 媒体下载续传修订）

- 情况：Mac 日志曾出现单张 200 随后单张 409，旧策略一概把 409 当成整批终止；普通 HTTP 404 已继续。不能把“文件身份/时间戳变化”与“章节正文变更”混为一谈。
- 用户动作：在媒体模块点击下载；其中一张远端图片返回 404，或 Mac CAS 返回 ESTALE / ECONFLICT。
- 预期：404 等图片级失败记录到对应 AG 行并继续。409 时必须先读取 *整个当前章节*，使用读取前后稳定的文件 revision 验证，逐字节与内存中未修改的 MD 对比，且当前工作目录、章节、草稿状态不变；内容一致只接纳新的 CAS identity，本张图片仍失败，继续后续图片。下一张仍经 Mac 端完整 CAS，不自动重试未知结果的非幂等下载请求。
- 安全不变量：任何正文不一致、章节已切换、未保存、文件读取不完整/验证失败、权限异常均停止整个批次；未处理列表明确显示原因。不得擅自覆盖变动章节，也不得借 metadata 刷新绕过服务端 CAS。
- 验收：浏览器隔离 Vault 加一组“成功 → metadata-only CAS 409 → 普通失败 → 后续成功”，对照真实章节字节与 AG / 顶栏，分别使用 Chromium 和 WebKit；保持已有“模拟冲突伴随正文不一致，整批停止”测试通过。真实 iPad Safari 人工验收待用户。
