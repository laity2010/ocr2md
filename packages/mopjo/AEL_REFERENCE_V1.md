## 其他模块应统一采集的指标

1. **基线与范围**：记录仓库/模块路径、版本、首次快照哈希、开始/结束时点、任务类型（新增、迁移、修复、重构）。
2. **边界**：跨模块私有导入数（目标始终为零）、修改文件的归属与跨边界告警；明确允许的公共 API / 第三方依赖。
3. **扩散**：修改文件总数、生产源文件数、`SPREAD` 次数、每次告警原因及是否经过人工确认；大规模有意迁移另行标记。
4. **测试**：必须保留原有回归数和结论、增量功能测试、退出码、可复现的固定样本、隔离测试环境；不把原始检查数量当成覆盖率。
5. **效率**：区分任务总体历时、单次构建耗时、单次测试耗时；仅比较相近硬件、同等样本、同等缓存/运行范围的数据。
6. **落盘/原件安全**：只读来源哈希、增量回放结果、生产事务是否在真实多设备环境验证、是否遗留未登记变化。

**共识规则**：边界越界原则上不接受；`SPREAD` 是需解释的提示而非简单失败；更改已有行为必须有对应回归；最终结论要明确区分独立模块验收、实际页面接入以及生产并发事务验收。先持续收集数个 WP 的同口径记录，再谈趋势和量化阈值。

## 新模块采用方式

以本模块的 [WP06_ARCHITECTURE.md](./WP06_ARCHITECTURE.md) 和 `scripts/ael.py` 为最小参考，**适配模块根路径、文件归属规则与测试命令**，而不是让新模块依赖 MOPJO 代码。用 `AEL_REFERENCE_V1.json` 这份同字段 JSON 作第一份跨模块样例；每个新模块都独立采集自己的快照，并保留迁移任务与常规业务开发的分类。所有模块的账本应相互隔离，WCP 内核不参与记账。
