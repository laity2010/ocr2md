# WP14 · 每个逻辑块对应 CM6 一个行号、只隔一个 LF

## 用户在 iPad Safari 的验收要求

OCR 基础块转换为逻辑块后，不能让 OCR 中一段文字的物理断行扩张为多条 CM6 源码行。每个 `logical_id` 对应唯一的源码行号；相邻块之间只保留一个回车换行。长文本在 iPad 上可以自动软折行，但不新增行号。该规则不取决于 PBS 是否同一父组。

## 数据权威与两表架构

- 原始 `mineru_base` 和 MinerUJSON/PDF 继续**完全无损且只读**。在生成新 `logical_block.md_block` 时，把 OCR 原文的连续 CR/LF 与相邻空白压为单个空格，不冒险猜测断词连字符；保留所有 OCR 文字和公式符号。title、正文、HTML 表格、caption、footnote 和显示数学统一单行（显示数学采用 V1 可直接渲染的 `$$公式$$`）。禁止额外业务表和 Markdown 行表。
- CM6 从 `md_block` 按 `logical_order` 投影，中间每一块仅一 LF，最后一个块不额外添加换行。虚拟 LF 属于前块区间，可区分真实 SQL 文本。`logicalTextRows` 读取回来的正文必须与现有持久化文本精确一致，结构拖动只更改 PBS/顺序。
- 对已经使用的旧书籍，**不执行自动迁移或重建**，因为可能包含人工编辑。SQL 组现有操作弹窗新增「整理逻辑块为单行」，二次确认后使用唯一 CM6 的一个文本编辑事务，将当前所有多行 MD Block 规范为单行；原生 Undo/Redo 生效，旧值比对的 `md-commit` 空闲提交保证遇并发冲突不覆盖别处修改。`logical_id/p/b/s` 和 `Raw Block` 不变。
- CM6 禁止 Enter / 换行粘贴引入第二条物理行到同一块；旧多行行块仍可正常只读加载并经显式整理。未开放的块拆分保持未开放。
- Markdown 阅读预览只读取**当前 CM6 的逻辑块清单**并临时用双 LF 分隔供 V1 Markdown-it 识别不同段落、表格和脚注；它只在预览侧重映射 source-line 位置，不在源码/SQLite 制造额外换行，也不建立第二份可编辑正文。

## 回归要求与风险

- 真实 267 行书籍中，新初始化必须恰好 267 条源码物理行，且每个 `md_block` 不含 CR/LF；MinerU JSON、基础表 SHA 不变；SQL Markdown 传输格式的双 LF 仅用于带 UTF-16 offsets 的网络传输，不得混入 CM6。
- 直接测试要涵盖中文、UTF-16、空块、表格、标题、`$$` 数学、尾部无回车，单行逆映射、PBS 拖动不改变行数。
- Chromium 和 iPad-WebKit 浏览器测试需检查 CM6 行数、真实 PDF 拖动、AG 定位、MD 预览及 Undo/Redo/SQL 旧值回写、旧书籍二次确认整理与拒绝直接多行输入。
- 已编辑的旧多行内容经过用户**明确确认整理**会删除其原有手工换行；不能自动猜测哪些换行有语义。代码围栏等内容若被整理也可能丢失多行块语法，按原生 Undo 回退；新数据原始块不受影响。对于是否需要更复杂的多行块专用视图，另行实验，不破坏此单行正文契约。
